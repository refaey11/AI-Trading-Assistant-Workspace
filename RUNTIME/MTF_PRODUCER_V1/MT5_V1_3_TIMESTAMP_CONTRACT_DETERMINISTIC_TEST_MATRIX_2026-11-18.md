## 1. Purpose

This matrix converts the V1.3 timestamp/observation proposal into explicit acceptance tests. It is a test design artifact only. It does not implement a capture EA, change a schema, or claim any test has passed.

Every test result must identify its evidence class:
- **FIXTURE:** deterministic test using controlled timestamps, clocks, and rows.
- **MT5-DEMO:** observation from the actual MT5 terminal/EA on a demo account.
- **SOURCE-CONTRACT:** evidence from authoritative MT5 API documentation or verified platform behavior.
- **COMBINED:** requires more than one of the above.

A fixture can prove our code handles a declared contract. It cannot prove that MT5 or a broker actually supplies the claimed timestamp semantics.

## 4. MT5-DEMO observation tests

These tests require controlled observation from the actual MT5 terminal/EA. A unit test alone cannot pass them.

| Test ID | Scenario | Required observation |
| --- | --- | --- |
| DEMO-01 | EA selects the latest closed bar using the documented CopyRates shift | Record symbol, timeframe, selected bar identity, API call/shift, and observation event |
| DEMO-02 | Repeat DEMO-01 for M5/M15/M30/H1/H4/D1 | Six explicit timeframe results |
| DEMO-03 | Observe around a period boundary | Show which bar is selected before and after the boundary; do not assume exact close time from duration arithmetic |
| DEMO-04 | No new tick / stale feed around expected boundary | Capture must not claim a fresh observation without evidence |
| DEMO-05 | Weekend and market-session gap | No synthetic bars or inferred close timestamps |
| DEMO-06 | Terminal disconnect and reconnect | No backdating of observation time; replayed bars retain original bar identity and new observation event |
| DEMO-07 | EA/terminal restart | No fabricated observation timestamp or duplicate conflict |
| DEMO-08 | Delayed availability after a bar boundary | Distinguish bar identity from the later observation time |
| DEMO-09 | Host clock deliberately differs from a trusted reference | Record the discrepancy; do not silently adjust source bar timestamps |
| DEMO-10 | Server and host clock diagnostics differ | Preserve clock domains; do not turn current offset into historical timezone policy |

For each DEMO test, preserve raw logs/CSV, terminal build, broker server identity, EA version, capture version, machine clock configuration, test time window, and an explanation of what the evidence can and cannot establish. Redact account credentials and private account identifiers.

## 6. Test execution and reporting rules

1. Use GitHub Actions only for automated repository tests.
2. Do not use CircleCI.
3. Keep deterministic fixture tests separate from MT5-DEMO evidence.
4. Report exact command, commit SHA, workflow run, test count, pass/fail/skip count, and timeframe coverage.
5. A successful Python test run does not prove broker clock correctness or actual bar-close semantics.
6. A manual MT5-DEMO observation does not replace deterministic regression tests.
7. Any test that depends on an unknown source contract must be marked BLOCKED, not passed by weakening the assertion.
8. Do not use 2025 for tuning, calibration, test selection, or acceptance thresholds.
9. Do not add formulas, direction, imputation, scaling, orders, or runtime integration as part of this test plan.

## 7. Gate decision

The V1.3 timestamp contract remains **NOT ACCEPTED / NOT IMPLEMENTED** until:
- authoritative source semantics are documented for every timestamp claimed;
- the required fixture suite passes on GitHub Actions;
- all six timeframe DEMO observations are captured and reviewed;
- schema backward compatibility with V1/V1.2 is proven;
- an independent compatibility review signs off.

Until then, Stage B remains PARTIAL; Stage C feature production and Stage D historical parity remain BLOCKED. The legacy 2016–2024 naive timestamps remain unresolved. 2025 remains locked OOS. No live trading is authorized.
